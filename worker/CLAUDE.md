# CLAUDE.md — harbinger/worker

TypeScript Cloudflare Worker + D1. Source of truth for harbinger; served only at `harbinger-api.aurlaw.dev`. Read the repo-root `CLAUDE.md` first — its working agreement applies here.

## Layout

- `src/index.ts` — ES module `fetch` handler: auth → route → catch-all 500
- `src/auth.ts` — API key gate (runs before routing)
- `src/router.ts` — hand-rolled `pathname → method → handler` map
- `src/http.ts` — `json()` / `errorResponse()`; every response goes through these
- `src/health.ts` — `GET /health`
- `src/body.ts` — `withJsonBody(validate, handle)`: 5 MB cap, JSON parse, validation → 413 / 400 before the handler runs; `InvalidRequest` error
- `src/validate.ts` — hand-rolled validators (throw `InvalidRequest` with the field path); `uniqueItems` rejects duplicate URIs in an array
- `src/library/` — W2 CLI endpoints: `films.ts` (list, upsert, override), `matches.ts`, `imports.ts` (import, latest), `shared.ts` (film columns, unknown-URI check)
- `migrations/` — D1 migrations, plain top-level `NNNN_name.sql` files
- `test/` — Vitest in the Workers runtime; own `tsconfig.json`
- `worker-configuration.d.ts` — generated by `npm run types`; never hand-edit

## Commands

- `npm run typecheck` — `src/` and `test/` (two tsconfigs)
- `npm test` — Vitest via `@cloudflare/vitest-pool-workers`
- `npm run types` — regenerate `worker-configuration.d.ts` after any `wrangler.jsonc` change or new entrypoint export
- `npm run dev`, `npm run db:migrate:local` — Michael runs these; Claude doesn't

Claude never runs `wrangler d1 create`, `wrangler secret put`, `wrangler deploy`, any `--remote` command, or git.

## Conventions

- **Dependencies:** zero runtime deps. Dev deps are `wrangler`, `typescript`, `vitest`, `@cloudflare/vitest-pool-workers` only; anything else must be justified and flagged. (`wrangler types` suggests `@types/node` — deliberately not installed; keep Node-only code out of the typechecked set.)
- **No framework, no ORM, no query builder.** Raw `env.DB.prepare(...)` with `.bind()` parameters only — never interpolate values into SQL.
- **Types:** `Env` comes from `wrangler types`. Don't hand-write `Env` or add `@cloudflare/workers-types`. `API_KEY` is typed via `secrets.required` in `wrangler.jsonc`, not inferred from `.dev.vars`.
- **Config:** `wrangler.jsonc` only. `workers_dev: false`, `preview_urls: false`; the custom domain is the only public entry point. `database_id` is a placeholder until Michael fills it in.
- **Auth:** every request, including unknown paths, needs `Authorization: Bearer <API_KEY>`. Auth runs before routing (unauthenticated unknown path → 401, not 404). Comparison is constant-time via `crypto.subtle.timingSafeEqual`; on length mismatch compare input to itself and negate — never return early. Fail closed: unset/empty `API_KEY` → 500 for every request.
- **Responses:** always `Content-Type: application/json` and `Cache-Control: no-store`. Errors are exactly `{ "error": { "code": "<string>", "message": "<string>" } }`. Log internal errors; never return them to the caller.
- **Routing:** add routes to the map in `src/router.ts`. Unknown path → 404 `not_found`; known path, wrong method → 405 `method_not_allowed` with `Allow`.
- **Error codes in use:** `unauthorized` (401), `not_found` (404), `method_not_allowed` (405), `internal_error` (500), `db_unavailable` (503), `invalid_json` (400), `invalid_request` (400), `payload_too_large` (413), `unknown_films` (422), `empty_snapshot` (409), `no_imports` (404).
- **Request bodies:** go through `withJsonBody`. Invalid JSON → `invalid_json`; wrong shape/type/range → `invalid_request` naming the first bad field; unknown extra fields ignored; > 5 MB (Content-Length or bytes read) → `payload_too_large`. Letterboxd URIs must start with `https://boxd.it/`.
- **Timestamps:** always `new Date().toISOString()`.

## Schema & migrations

- The schema in the vault's `data-mapping.md` is canonical. Migrations implement it exactly; if it looks wrong, flag it — don't change it.
- `0001_initial_schema.sql` = Library schema (W1). `0002_recommendations.sql` = Recommendation schema (W4). Never edit an applied migration; add a new one.
- A migration file must **not end with a comment line** (breaks `applyD1Migrations` in tests).
- D1 enforces foreign keys; tests rely on that.

## Bulk SQL

D1 caps bound parameters at 100 per query and queries at 1,000 per invocation. Every endpoint must use a small, **fixed** number of statements regardless of payload size — never multi-row `VALUES`, never one statement per item.

- Pass each array as **one** bound JSON-string parameter and expand it with `json_each(?)` / `json_extract(value, '$.field')`
- Upsert from `json_each`: `INSERT ... SELECT ... FROM json_each(?) WHERE true ON CONFLICT(...) DO UPDATE ...` — **the `WHERE true` is required**; SQLite can't parse `ON CONFLICT` directly after `SELECT ... FROM`
- Bulk update: `UPDATE films SET ... FROM (SELECT ... FROM json_each(?)) AS m WHERE films.letterboxd_uri = m.letterboxd_uri`
- Existence check: `SELECT value FROM json_each(?) WHERE value NOT IN (SELECT letterboxd_uri FROM films)`
- Multi-statement writes that must be atomic go in one `env.DB.batch()` (a failed statement rolls back the batch). `RETURNING` works inside a batch
- Pre-`JSON.stringify` nested objects (e.g. `tmdb_json`) in TS before building the payload, so the stored text is exactly `JSON.stringify` output
- Tests must include ~1,000-item requests; three-row fixtures won't catch these limits

## Testing

- `vitest.config.ts` uses the `cloudflareTest` plugin and `readD1Migrations`, both imported from the `@cloudflare/vitest-pool-workers` package root (not `/config` — older docs are wrong for this version).
- Migrations are applied in `test/apply-migrations.ts` from the test-only `TEST_MIGRATIONS` binding (typed in `test/env.d.ts`).
- D1 storage is isolated per test **file** but shared between tests in a file — W2 files call `clearLibrary()` in `beforeEach`. Shared request/assert helpers live in `test/helpers.ts`.
- `Date.now()` only advances across I/O in workerd; use `tick()` from helpers when a test needs distinct timestamps.
- Tests get `API_KEY=test-api-key` from `vitest.config.ts`, which overrides any local `.dev.vars`.
- Import `env` / `exports` from `cloudflare:workers`; `env` and `SELF` from `cloudflare:test` are deprecated in this version. To test with altered bindings (e.g. unset `API_KEY`, failing `DB`), import the handler from `src/index` and call `worker.fetch(request, { ...env, ...overrides })`.
- Pool 0.22 requires `vitest` 4.x — don't let npm bump it to 5.
