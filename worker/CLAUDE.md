# CLAUDE.md — harbinger/worker

TypeScript Cloudflare Worker + D1. Source of truth for harbinger; served only at `harbinger-api.aurlaw.dev`. Read the repo-root `CLAUDE.md` first — its working agreement applies here.

## Layout

- `src/index.ts` — ES module `fetch` handler: auth → route → catch-all 500
- `src/auth.ts` — API key gate (runs before routing)
- `src/router.ts` — hand-rolled `pathname → method → handler` map, plus a short list of parameterized routes
- `src/http.ts` — `json()` / `errorResponse()`; every response goes through these
- `src/health.ts` — `GET /health`
- `src/body.ts` — `withJsonBody(validate, handle)`: 5 MB cap, JSON parse, validation → 413 / 400 before the handler runs; `InvalidRequest` error
- `src/validate.ts` — hand-rolled validators (throw `InvalidRequest` with the field path); `uniqueItems` rejects duplicate URIs in an array
- `src/library/` — W2 CLI endpoints: `films.ts` (list, upsert, override), `matches.ts`, `imports.ts` (import, latest), `shared.ts` (film columns, unknown-URI check)
- `src/tmdb/client.ts` — the only code that talks to TMDB: `tmdbGet` (base URL, auth header, `language=en-US`, 10 s timeout, error mapping → `TmdbError`), `withTmdbErrors`. Reused by W4
- `src/tmdb/search.ts` — `GET /tmdb/search` handler; `toSearchPage` / `toSearchResult` mapping
- `src/tmdb/movie.ts` — `GET /tmdb/movie/{id}` handler; `toMovieDetails` mapping and `HORROR_GENRE_ID` (the single server-side horror rule). Its output is exactly `films.tmdb_json`
- `src/claude/client.ts` — the only code that talks to Anthropic: `claudeConfig` (fail-closed config check), `callClaude` (headers, `output_config.format`, top-level `cache_control`, 90 s timeout, retry, error mapping → `ClaudeError`, usage log)
- `src/recommend/schema.ts` — `OUTPUT_SCHEMA` (the one constant structured-output schema) and `parseReply` (Worker-side validation of Claude's JSON)
- `src/recommend/prompt.ts` — library queries, `buildSystemPrompt` (with the W5 `tasteProfile` hook), `userTurnText` (recommend-now line), `replayTurns`
- `src/recommend/resolve.ts` — pick → TMDB film via `tmdbGet` in-process (primary-year search, then `year` fallback, normalized title ±1 year), then one enriched details call
- `src/recommend/validate.ts` — `loadExclusionSet` (once per request) and `checkPick` (per-pick rejection reason)
- `src/recommend/replace.ts` — `pickFilms`: resolve → validate the first reply, then up to `MAX_REPLACEMENT_ROUNDS` replacement rounds; rejection + summary logs
- `src/tmdb/enrich.ts` — `fetchEnrichedDetails` / `toEnrichedDetails`: `MovieDetails` + director, US providers, providers link, trailer
- `src/recommend/normalize.ts` — TS port of the CLI's `normalize.Title`
- `src/conversations/handlers.ts` — `GET /models`, `POST /conversations`, `POST /conversations/{id}/messages`, `GET /conversations/{id}`; `converse` runs one exchange
- `src/conversations/store.ts` — D1 load / atomic `saveTurn` batch, row → API mappers
- `migrations/` — D1 migrations, plain top-level `NNNN_name.sql` files
- `test/` — Vitest in the Workers runtime; own `tsconfig.json`
- `worker-configuration.d.ts` — generated by `npm run types`; never hand-edit

## Commands

- `npm run typecheck` — `src/` and `test/` (two tsconfigs)
- `npm test` — Vitest via `@cloudflare/vitest-pool-workers`
- `npm run types` — regenerate `worker-configuration.d.ts` after any `wrangler.jsonc` change or new entrypoint export
- `npm run dev`, `npm run db:migrate:local` — Michael runs these; Claude doesn't

Claude never runs `wrangler d1 create`, `wrangler secret put`, `wrangler deploy`, any `--remote` command, or git.

## Conventions

- **Dependencies:** zero runtime deps. Dev deps are `wrangler`, `typescript`, `vitest`, `@cloudflare/vitest-pool-workers` only; anything else must be justified and flagged. (`wrangler types` suggests `@types/node` — deliberately not installed; keep Node-only code out of the typechecked set.)
- **No framework, no ORM, no query builder.** Raw `env.DB.prepare(...)` with `.bind()` parameters only — never interpolate values into SQL.
- **Types:** `Env` comes from `wrangler types`. Don't hand-write `Env` or add `@cloudflare/workers-types`. `API_KEY` is typed via `secrets.required` in `wrangler.jsonc`, not inferred from `.dev.vars`.
- **Config:** `wrangler.jsonc` only. `workers_dev: false`, `preview_urls: false`; the custom domain is the only public entry point. `database_id` is a placeholder until Michael fills it in.
- **Auth:** every request, including unknown paths, needs `Authorization: Bearer <API_KEY>`. Auth runs before routing (unauthenticated unknown path → 401, not 404). Comparison is constant-time via `crypto.subtle.timingSafeEqual`; on length mismatch compare input to itself and negate — never return early. Fail closed: unset/empty `API_KEY` → 500 for every request.
- **Responses:** always `Content-Type: application/json` and `Cache-Control: no-store`. Errors are exactly `{ "error": { "code": "<string>", "message": "<string>" } }`. Log internal errors; never return them to the caller.
- **Routing:** add routes to the map in `src/router.ts`. Unknown path → 404 `not_found`; known path, wrong method → 405 `method_not_allowed` with `Allow`. Routes with a path parameter go in `paramRoutes` (a regex with named groups, checked after the static map); the groups are passed to the handler as its third `params` argument. Same 404/405 semantics. The pattern only captures a segment (`[^/]+`) — the handler validates it (→ 400). No routing library.
- **Error codes in use:** `unauthorized` (401), `not_found` (404), `method_not_allowed` (405), `internal_error` (500), `db_unavailable` (503), `invalid_json` (400), `invalid_request` (400), `payload_too_large` (413), `unknown_films` (422), `empty_snapshot` (409), `no_imports` (404), `tmdb_unavailable` (502), `tmdb_rate_limited` (503), `invalid_model` (400), `claude_unavailable` (503), `claude_error` (502), `recommendation_failed` (502), `conversation_busy` (409).
- **Request bodies:** go through `withJsonBody`. Invalid JSON → `invalid_json`; wrong shape/type/range → `invalid_request` naming the first bad field; unknown extra fields ignored; > 5 MB (Content-Length or bytes read) → `payload_too_large`. Letterboxd URIs must start with `https://boxd.it/`.
- **TMDB:** only `src/tmdb/client.ts` calls TMDB. Build URLs with `URL` / `URLSearchParams`, never string concatenation of user input. Responses are fixed, trimmed shapes — never forward TMDB's body or status text. TMDB 404 → `not_found`; 401/403 → `tmdb_unavailable` (logged as an auth failure); 429 → `tmdb_rate_limited` with `Retry-After` passed through; 5xx / network / timeout / non-JSON → `tmdb_unavailable`. No caching of TMDB responses. The token is never logged or returned.
- **Claude:** only `src/claude/client.ts` calls Anthropic. Native `fetch`, **no Anthropic SDK**. `POST {ANTHROPIC_BASE_URL}/v1/messages` with `x-api-key`, `anthropic-version: 2023-06-01`; body `model`, `max_tokens: 4096`, `system`, `messages`, `output_config.format` (`json_schema`; **not** the deprecated `output_format`), top-level `cache_control: { type: "ephemeral" }`. The JSON is read from the `text` content block (thinking blocks may precede it). Only `stop_reason: end_turn` is parsed; `refusal` / `max_tokens` → `claude_error`. 429/529 → `claude_unavailable` (`Retry-After` passed through); 5xx / network / timeout → one retry after 1 s, then `claude_error`; 4xx → `claude_error` with status + Anthropic error type logged. Never forward Anthropic's body. One `claude_usage` JSON log line per call (model, input / cache-creation / cache-read / output tokens, stop reason). The key is never logged or returned.
- **Prompt caching rules:** `OUTPUT_SCHEMA` is **constant** — never vary `output_config.format` per request (it invalidates the cache); question-vs-recommend is steered by instructions only. The system prompt depends only on library state: every list query has a total `ORDER BY`, nothing per-request (no timestamps, ids, model names) goes in it. Per-turn steering ("Recommend now") is appended to the **user turn**, never the system prompt. Replayed turns are re-serialized deterministically (`replayTurns`) so earlier turns stay cache-hittable.
- **Conversations:** a whole exchange is one `env.DB.batch()` written only after Claude and TMDB succeed; seq collision → `conversation_busy`. Must-recommend (`just_pick` or `question_rounds = 2`) + question reply → one firmer retry, then `recommendation_failed`. A first recommendations reply with zero valid-shaped picks → `recommendation_failed`.
- **Pick validation** (`checkPick`, first failing reason wins): an earlier-rejected `tmdb_id` in this request → `duplicate`; `not_horror` (genre 27 absent — TMDB's genres only, no library override); `not_feature` (known runtime < 40 min; unknown passes); `excluded`; `duplicate` (already accepted in this reply). Unresolvable → `unresolved`; schema-invalid → `invalid`.
- **Exclusion set** (`loadExclusionSet`, once per request, the `data-mapping.md` query): global = `tmdb_id` of watched ∪ watchlist films (any genre) + `yes` / `no` decisions; this conversation = its `maybe` decisions + every `recommendations.tmdb_id` already stored for it (skipped for a new conversation); fallback = watched / watchlist films with `tmdb_id IS NULL`, matched by normalized title + year ±1. `decisions` is read only — no writer until W5.
- **Replacement loop** (`pickFilms`): target = valid-shaped picks in the first reply (≤ 5; never pad a deliberate short reply). While accepted < target, at most **2** rounds: same model, system prompt, and schema; messages = history + user turn + each assistant reply (JSON as returned) + a replacement user turn listing **all** rejections so far with reason phrases, the count needed, and the recommend-now line. A question (or unusable) reply = zero-pick round. Extras beyond target discarded. Order: originals, then replacements; positions contiguous. Only the user message and final assistant message are stored; `content_json.dropped` = total rejections. 0 accepted after the cap → `recommendation_failed`. Logs one `pick_rejected` line per rejection (title, year, reason, round) and one `pick_summary` per request (target, accepted, rejected, rounds).
- **Enrichment** (`src/tmdb/enrich.ts`): one `GET /movie/{id}?append_to_response=credits,videos,watch/providers`. TMDB keys the appended section by the literal string **`"watch/providers"`** — read it as `raw["watch/providers"]`. `director` = crew `job === "Director"` names, ordered, de-duplicated, `", "`-joined, else `null`. `providers` = `results.US` entries from `flatrate`, `free`, `ads`, `rent`, `buy` in that order as `{ name, type, logo_path }`, de-duplicated by name keeping the first type; `providers_link` = `results.US.link`. `trailer_key` = YouTube only; official Trailer > Trailer > Teaser, latest `published_at` within a tier. Absent / malformed sections → `null` / `[]` — never fail resolution. `recommendations.tmdb_json` stores `EnrichedDetails`; `toMovieDetails` and `GET /tmdb/movie/{id}` are unchanged (CLI contract). Rows without enrichment render as `null` / `[]` / `null` (no backfill).
- **Timestamps:** always `new Date().toISOString()`.

## Schema & migrations

- The schema in the vault's `data-mapping.md` is canonical. Migrations implement it exactly; if it looks wrong, flag it — don't change it.
- `0001_initial_schema.sql` = Library schema (W1). `0002_recommendations.sql` = Recommendation schema (W4). Never edit an applied migration; add a new one.
- A migration file must **not end with a comment line** (breaks `applyD1Migrations` in tests).
- D1 enforces foreign keys; tests rely on that.

## Bulk SQL

D1 caps bound parameters at 100 per query and queries at 1,000 per invocation. Every endpoint must use a small, **fixed** number of statements regardless of payload size — never multi-row `VALUES`, never one statement per item.

- Pass each array as **one** bound JSON-string parameter and expand it with `json_each(?)` / `json_extract(value, '$.field')`
- Upsert from `json_each`: `INSERT ... SELECT ... FROM json_each(?) WHERE true ON CONFLICT(...) DO UPDATE ...` — **the `WHERE true` is required**; SQLite can't parse `ON CONFLICT` directly after `SELECT ... FROM`
- Bulk update: `UPDATE films SET ... FROM (SELECT ... FROM json_each(?)) AS m WHERE films.letterboxd_uri = m.letterboxd_uri`
- Existence check: `SELECT value FROM json_each(?) WHERE value NOT IN (SELECT letterboxd_uri FROM films)`
- Multi-statement writes that must be atomic go in one `env.DB.batch()` (a failed statement rolls back the batch). `RETURNING` works inside a batch
- Pre-`JSON.stringify` nested objects (e.g. `tmdb_json`) in TS before building the payload, so the stored text is exactly `JSON.stringify` output
- Tests must include ~1,000-item requests; three-row fixtures won't catch these limits

## Testing

- `vitest.config.ts` uses the `cloudflareTest` plugin and `readD1Migrations`, both imported from the `@cloudflare/vitest-pool-workers` package root (not `/config` — older docs are wrong for this version).
- Migrations are applied in `test/apply-migrations.ts` from the test-only `TEST_MIGRATIONS` binding (typed in `test/env.d.ts`).
- D1 storage is isolated per test **file** but shared between tests in a file — W2 files call `clearLibrary()` in `beforeEach`. Shared request/assert helpers live in `test/helpers.ts`.
- `Date.now()` only advances across I/O in workerd; use `tick()` from helpers when a test needs distinct timestamps.
- Tests get `API_KEY=test-api-key` from `vitest.config.ts`, which overrides any local `.dev.vars`.
- Import `env` / `exports` from `cloudflare:workers`; `env` and `SELF` from `cloudflare:test` are deprecated in this version. To test with altered bindings (e.g. unset `API_KEY`, failing `DB`), import the handler from `src/index` and call `worker.fetch(request, { ...env, ...overrides })`.
- **Outbound fetch:** `fetchMock` from `cloudflare:test` no longer exists in this pool version. Mock with `vi.spyOn(globalThis, "fetch")` (it intercepts the Worker's calls) and `vi.restoreAllMocks()` in `afterEach`. The mock must throw on any unexpected URL. No MSW or other new dev dependencies.
- Tests get `TMDB_READ_TOKEN=test-tmdb-token` and `ANTHROPIC_API_KEY=test-anthropic-key` from `vitest.config.ts`. The "Missing required secrets: TMDB_READ_TOKEN" warning during `npm test` just means `.dev.vars` lacks it; the Miniflare binding still applies.
- Pool 0.22 requires `vitest` 4.x — don't let npm bump it to 5.
- **Conversation tests** use `mockWorld` in `test/conversations-helpers.ts`: queued Anthropic replies plus an in-memory TMDB catalog; anything else throws. Queued replies are **thunks** — workerd forbids reading a `Response` body created in another request's context. Never call the real Anthropic API from tests.
- **Non-ASCII in source:** write `\uXXXX`-style characters via `String.fromCodePoint(...)`, not escapes typed into files — tooling has converted escapes into raw characters (a raw U+2028 breaks a regex literal).

## Secrets

All listed in `secrets.required` in `wrangler.jsonc`; locally in `.dev.vars` (gitignored; copy from `.dev.vars.example`), remotely via `npx wrangler secret put <NAME>` (Michael). Nothing secret in the repo.

- `API_KEY` — the harbinger API key. Unset/empty → 500 for every request.
- `TMDB_READ_TOKEN` — TMDB v4 API Read Access Token. Unset/empty → 500 `internal_error` (logged) on `/tmdb/*` and the conversation routes (which resolve picks on TMDB), with no outbound request; every other route is unaffected. Never logged, echoed, or returned.
- `ANTHROPIC_API_KEY` — Claude API key. Unset/empty → 500 `internal_error` (logged) on `/models` and `/conversations*` only, with no outbound request; every other route is unaffected. Never logged, echoed, or returned.

Vars (`wrangler.jsonc` `vars`, not secret): `ANTHROPIC_BASE_URL` (`https://api.anthropic.com`; exists so Phase 2 can move behind AI Gateway by config only), `CLAUDE_MODELS` (comma-separated allowlist), `CLAUDE_DEFAULT_MODEL` (must be in `CLAUDE_MODELS`, else conversation routes 500).
